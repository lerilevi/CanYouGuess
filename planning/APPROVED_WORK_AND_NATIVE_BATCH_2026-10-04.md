# Approved repair, recovery and first native batch

Updated October 4, 2026. Supersedes the earlier guest/email and pilot proposals. Main and TestFlight build 19 are unchanged. No cloud compilation, native package change, hosted deployment, or paid AI request is authorized by this document alone.

## Execution status and deployment gate

Identity repair is implemented on `integration/onspace-exit`: synchronous auth ownership publication; keyed routed subtree; generation-scoped async guards; project+UID cache envelopes; captured JWT requests; ordered RevenueCat configure → UID sync → customer-info refresh; unknown purchase state instead of another player's paid value. Game answers, drafts, stats, badges, modals and category state reset on identity transition. Missing data clears instead of retaining A. Client score/counter/badge writes are removed. Logout and deletion cannot perform a second late sign-out of B.

The integration client now requires the target backend contract; it does NOT fall back to the old backend. Its local `.env`, build 19 and hosted function have NOT been switched. Do not publish this branch to a build-19 OTA channel. Target rollout must apply migration 0006 and deploy the matching function together, then select the new project explicitly. It is not yet a usable old-backend TestFlight patch.

Server migration 0006 reserves every delivered question before Gemini, under a per-UID profile-row lock. Home, Categories, retry and direct API generation use the same gate. Successful deliveries consume allowance even when discarded; failed/expired pending generation reservations refund. A duplicate request ID replays the public question rather than calling Gemini again. Evaluation only accepts the owner's server session ID. No arbitrary score/answer/reference comes from the client.

Premium comes from a server RevenueCat verification, not the client's boolean. Required server secrets/config: `REVENUECAT_SECRET_KEY`, `REVENUECAT_ENTITLEMENT_ID`; `ALLOW_SANDBOX_PURCHASES=true` ONLY for the isolated beta environment. Unknown sandbox provenance fails closed. These values and the actual RevenueCat restore policy still need secure dashboard verification. Refund/revocation webhook reconciliation remains part of the monetization integration; the new polling cache expires in five minutes and generation verifies again. It is not a complete billing system yet.

Client ad callbacks no longer mint bonus credits. The old local bonus/guest/consent/history keys are not imported. Reward intents, AdMob signature verification, duplicate transaction handling and reconciliation are still needed; until that adapter exists, the offer is deliberately unavailable. This is an explicit safety gate, NOT a claim that the missing rewarded-ad UI is repaired. One verified reward will mint one credit, with server-configurable value/cooldown/technical ceiling and no product daily cap. Migration defaults are provisional safety settings, not economics findings.

Daily allowance is server-clock based in validated IANA timezone. Initial timezone is selected before first play. After play starts, a timezone change queues a future local midnight, never shortens the current reset, adds at least a 20-hour travel guard and has a seven-day change cooldown. Allowance and streak finalization share the protected window date. Revisited dates retain consumed usage. Normal DST days reset at their actual local midnight (23/25 hours); only travel can extend a window. Client clock changes cannot grant questions. A question delivered before midnight and answered after it consumes its delivery window's allowance but counts play/streak at finalization in the active window. Ranked mode stays postponed.

Local verification: `npm run typecheck`; Deno check of function/pilot; local iOS Hermes export; 12 real-source React identity/race/offline regression cases; six ephemeral PostgreSQL/WASM migration/privilege/session test groups; eight bounded-pilot/rubric/alias groups. Historical repro replays commit 5147578 and still reproduces all seven original defects. The WASM DB is an isolated diagnostic dependency, not a mobile dependency. The updated hosted pgTAP/Edge suite has not been run without target access/Docker. Local checks do not replace hosted Supabase Auth, independent database-session concurrency, actual SDK, or device tests. No Mac/EAS slot is used for these checks.

## Physical-device A/B gate

Needs the registered iPhone plus the approved development-client native batch, two distinct test UIDs on the target project (A paid sandbox, B free), a known server entitlement/usage baseline, and safe UID-only diagnostics (no JWTs/receipts/emails). Build 19 cannot run this new JS until a compatible dev client or approved update runtime exists.

1. A answers a question, earns stats/badges, accepts the AI notice, and opens a purchase modal. Log out and choose B. Before B's network responses, no A answer, draft, badges, modal, consent or paid label may be visible.
2. Delay A generation, evaluation, stats and entitlement responses with a network proxy/deferred test adapter; switch B, then release them. B must remain unchanged; A's already-dispatched server work can finish only in A's ledger.
3. Go offline during the switch and RevenueCat refresh. B must show loading/unavailable, never A's paid status or cached result. Reconnect and refresh. Repeat B → A, A → logout → A, background/resume and five cold launches.
4. Exhaust B's 15 delivered questions. Home, Categories, Random, retry and concurrent direct requests must all be denied before provider spending. Failed provider requests refund, delivered/discarded ones do not. A's paid verification must not unlock B. Test restoration separately: OS receipt ownership can transfer according to RevenueCat policy and is not the same as a JS leak.
5. Change timezone/clock; confirm server reset unchanged immediately. Test travel cooldown, protected rollover, DST, in-flight midnight answer, duplicate evaluation and deletion (including deletion response after switching B).
6. Inspect project+UID caches. No old project's guest usage/bonus/consent is adopted. Do NOT clear OS tracking permission or Google's UMP consent on account switch; those are device/legal choices. AI-notice acknowledgement, history and preferences are user-owned. Auth persistence already uses Supabase's project storage key; project cutover is an explicit empty-beta reset.

Remaining device-scoped storage is intentional: the IP-country cache is only a location hint, not a selected profile country/leaderboard authority; onboarding completion is a device tutorial flag, not age or AI consent; fatal-report storage is device diagnostic evidence and must be redacted before external reporting. Mock-auth storage is not a production account source. OS/RevenueCat receipt ownership is distinct from the explicitly synchronized Supabase UID; verify restore transfer policy on device.

## Guest-first recovery, no SMTP

Anonymous Supabase accounts are authenticated UIDs, not the public `anon` database role. Their allowances, score/session ledger and RevenueCat appUserID use that UID. Nickname is only a display field, never a login or authority. Fresh install/reinstallation or lost local session creates a new UID; CAPTCHA is not a device uniqueness guarantee. Retain server/IP spend controls, global circuit breaker, account creation limits, nickname moderation/reporting and deletion. Guest-first removes email delivery operations; it does not remove account/security responsibilities. [Supabase anonymous users](https://supabase.com/docs/guides/auth/auth-anonymous)

Recommend native Sign in with Apple for iOS, behind a provider-neutral `linkRecoveryIdentity(provider, credential)` contract. No SMTP or app-owned email/password database is needed. Apple may supply a private-relay email; do not make it the identity key. Explicitly link the identity to the CURRENT anonymous user; then assert pre/post UID equality. This preserves the ledger and RevenueCat purchase ID. A fresh `signInWithIdToken` is NOT the guest-upgrade operation. If Apple identity already belongs to another account, stop and offer recovery/sign-in with a clear choice; do not silently merge scores, credits or purchases. [Identity linking](https://supabase.com/docs/guides/auth/auth-identity-linking), [Apple setup](https://supabase.com/docs/guides/auth/social-login/auth-apple)

Important compatibility check: installed Supabase 2.50 exposes OAuth `linkIdentity` but not the newer native-ID-token overload shown in current docs. Use a tested JS SDK upgrade to support token linking (no Expo SDK upgrade), or the explicitly supported OAuth linking path. This must be verified against the target Auth version before promising UID preservation in the actual app. Native Apple authentication belongs in the FIRST batch; do not postpone recovery until after paid release.

Apple requirements: `expo-apple-authentication` compatible with SDK 53; `ios.usesAppleSignIn`; config plugin/capability and regenerated provisioning; correct bundle audience in Supabase Apple provider; nonce verification; official Apple sign-in button. Secure Apple team/key configuration for authorization-code exchange/revocation when deleting a linked account. Native sign-in avoids the web OAuth client-secret rotation requirement, but deletion/revocation still needs a deliberate server credential flow. Android later can add Google/another provider behind the same linking contract without re-keying ledgers. [Expo Apple integration](https://docs.expo.dev/versions/latest/sdk/apple-authentication/), [Apple deletion guidance](https://developer.apple.com/support/offering-account-deletion-in-your-app/)

Recommended prompt policy (implement with guest rollout, not yet shipped): persistent Profile “Save my progress”; one gentle nudge after the first completed game session (or five answers, whichever is first), repeat after the third active local day with a seven-day dismissal cooldown; an explicit save/recovery choice BEFORE purchase. For the beta, require linking before starting a paid transaction: a lifetime purchase attached to an unrecoverable guest is an avoidable support problem. Explain that reinstalling without linking loses game history. Restore Purchases can restore access under the store/RevenueCat policy; it cannot reconstruct lost score history. Do not imply restoration guarantees the original UID. [RevenueCat identities](https://www.revenuecat.com/docs/customers/identifying-customers), [restore behavior](https://www.revenuecat.com/docs/projects/restore-behavior)

Do not allow unlinking the last recovery method without a clear loss warning/re-authentication policy. In-app Delete account is required even for guests; linked Apple deletion must revoke credentials appropriately. Nickname moderation must precede public leaderboards; duplicate display names may be disambiguated without treating a nickname as an account credential. Domain purchase remains on hold. CAPTCHA can use a stable HTTPS page on a free host; allowlist its hostname and verify tokens server-side via Supabase, with origin/navigation checks in the mobile WebView. [CAPTCHA](https://supabase.com/docs/guides/auth/auth-captcha), [Turnstile mobile](https://developers.cloudflare.com/turnstile/get-started/mobile-implementation/)
